官方当前文档提供 `account/login/start`、`account/login/completed`、`account/login/cancel`，并区分浏览器 `chatgpt` 与设备码 `chatgptDeviceCode`。前者由 App Server 接收浏览器回调；两者均由它维护认证流程。实现以本机版本支持情况为准，不将底层 HTTP 授权端点描述为有稳定保证的公共 API。[官方认证文档](https://learn.chatgpt.com/docs/app-server#auth-endpoints)

## 3. 登录体验与边界

新增账号提供三个入口：

1. **本地 Codex 登录**：检测到受支持运行时后推荐；打开官方运行时返回的浏览器授权地址。
2. **使用设备码登录**：支持时由同一本机运行时托管；缺失或明确不支持时可选择现有兼容实现。
3. **保存当前账号**：沿用用户在官方客户端完成登录后的本地保存流程。

界面说明“调用本机 Codex 完成授权”，避免暗示本工具属于官方产品。现有 Device OAuth 入口继续可用，默认入口只在兼容性验收后调整。

拟调整的产品行为：授权完成后默认只写入账号库，显示“账号已保存”，提供“切换到此账号”。这与当前新增登录立即激活不同，需同步更新中英文说明。切换继续使用现有“仅切换 / 切换并重启”行为与偏好。切换失败保留已保存账号，并准确显示失败阶段。

浏览器等待阶段不改变真实 `CODEX_HOME`、当前账号、API Key 配置或运行中的桌面客户端。临时 Home 单独指定文件凭据存储；真实 Home 的 `auto`、`keyring` 不被静默更改。首期仍按现有文件模式边界提供账号管理，不扩展为跨平台钥匙串管理。

## 4. 建议实施顺序

### P0：来源核对与可执行规格（本次已完成规划，运行验证待做）

- 固定上述许可证证据与实现来源规则。
- 在开发环境只读确认目标 Codex 版本和协议 schema，确定最低可支持的浏览器与设备码流程；不凭在线最新文档猜测用户本机能力。
- 定义运行时错误：未安装、不可执行、版本或方法不支持、回调端口冲突、网络失败、限流、授权撤销。诊断不携带原始协议消息或子进程输出。
- 首期复用本机 CLI / 可执行的内置运行时。Windows 商店目录拒绝执行时尝试经过验证的其他运行时候选，或提示设备码 / 本地保存；不把此错误误报成账号失效。

验收：能够用假进程覆盖初始化和能力差异，不登录真实账号、不修改当前认证文件。

### P1：官方托管登录后端

- 新增登录协调模块，复用并按需提取 App Server 进程和 RPC 基础代码。使用一个读循环，分别分发响应和通知，防止丢失提前到达的登录完成事件。
- 在应用私有目录创建每次独立的临时 Home，以 stdio 启动子进程；单独限制 RPC 初始化、浏览器等待、停止和清理的时间。
- 临时环境仅继承必要系统信息和用户代理选择，移除会抢占身份的 API Key / access-token 环境变量，不加载用户项目的插件、MCP 或模型供应商配置。
- 使用本工具真实 `clientInfo`；只调用登录所需的官方托管能力，不自行增加 scope，不使用外部令牌注入模式。
- 后端保留官方 loginId、进程句柄、临时路径和认证数据。前端只得到本工具 sessionId、必要授权地址或配对码、状态和安全错误码；授权材料不记录到日志和持久化 UI 状态。
- 前端刷新或重新挂载可查询当前会话状态；同一时刻只允许一个新增登录会话，切换方式先结束旧会话。
- 授权成功后核对账号信息，结束并等待本次子进程，再回读最终凭据并校验身份一致性。之后提交账号库，不把可选额度查询作为登录成功的前置条件。

验收：浏览器和设备码均可完成；旧进程、旧事件、重复通知不会产生重复账号或覆盖新会话。

### P2：保存、切换和清理闭环

- 分离“保存授权结果”和“激活已保存账号”，所有新增登录入口统一使用此语义。重新授权指定账号时核对身份，误登另一账号不得覆盖目标。
- 凭据提交在协调锁内完成；等待浏览器不占用全局操作锁。账号相同但授权代次不同，也不能用旧查询结果覆盖新登录。
- 会话状态包含准备、等待授权、校验、保存、成功、失败、取消、到期。提交与取消有明确先后关系：取消先完成则不再写入；提交已经完成则返回真实成功状态。
- 账号库写入失败不报告成功；激活失败不回滚已保存的新凭据。保存失败产生的临时数据只允许在受控短期恢复流程中保留，不能无限期残留。
- 正常完成、失败、取消和退出均终止本次子进程并清理对应临时目录；启动时清理过期残留。只清理程序记录且位于私有根目录内的任务目录，拒绝符号链接逃逸和任意路径删除。
- 清理采用结束进程和删除本地临时副本，不调用可能使已保存凭据失效的远端登出。文件删除不宣称为磁盘安全擦除。
- Unix 下目录 `0700`、凭据 `0600`；Windows 验证临时目录继承的是当前用户私有访问权限。原始令牌、认证文件、完整授权 URL 和原始 stderr 不进入日志或错误。

验收：取消、超时、应用重启、磁盘失败、重复完成和保存后切换失败均有明确结果；真实 Home 在用户发起切换前保持不变。

### P3：刷新协调、兼容降级与发布

- 新授权提交、账号切换、额度查询和迁移使用一致的锁顺序与账号身份规则，复用已有按账号串行和比较原凭据再写入机制。
- 对明确授权撤销返回重新登录状态；网络超时、429、未知字段等不直接标记授权失效。JWT 到期值只作辅助信息。
- 仅在运行时不可用或明确缺少能力时提供兼容路径；已经授权失败时不静默切到另一种实现反复登录。相同逻辑操作只允许受控的一次恢复，不叠加 App Server 和 HTTP 层的无限刷新。
- 本工具内部锁不能阻止独立 CLI、IDE 和桌面客户端刷新。外部认证文件已变化时重新读取并拒绝覆盖；不声称消除了跨进程刷新竞争。涉及多实例无法证明安全的操作保持人工重启路径。
- 首期记录登录方式和不含秘密的失败分类供本机诊断，不新增遥测、账号后台或远端功能开关。
- macOS、Windows、Linux 分别完成实际运行时冒烟验证，再把已验证的托管登录设为推荐。已有账号和切换入口应保持可用；不触碰版本号，正式发版遵循仓库 release 脚本。

### 后续可选：桌面客户端临时实例

只有当测试证实 App Server 托管登录仍存在桌面特有问题时，再单独评估一次性桌面实例。需要验证 `CODEX_HOME`、单实例复用、商店应用激活和钥匙串归属；不能只凭传入环境变量就假定完全隔离。首期不引入 Electron 注入、浏览器跳转拦截或客户端修改。

该阶段并非解决掉登录的承诺；授权托管、令牌刷新和远端会话有效性是不同问题。

## 5. 必须覆盖的验证

| 场景 | 验收标准 |
| --- | --- |
| 成功、重复通知、完成通知先于其他响应 | 只保存一次，前端可恢复正确状态 |
| 等待时取消、请求中取消、提交与取消竞争 | 取消成功后无迟到写入；已完成提交不谎报取消 |
| 已有账号重新授权、误登其他账号 | 身份匹配后更新；误登不得覆盖指定账号 |
| 保存失败、磁盘满、激活失败 | 错误阶段准确，已保存的新凭据不丢失 |
| 同账号额度查询与重新授权并行 | 旧结果不能覆盖新授权；锁顺序无死锁 |
| 外部客户端修改当前认证文件 | 检出变化，不把旧快照覆盖回去 |
| runtime 缺失、旧版、不可执行、回调端口占用 | 提供对应恢复入口，不误报服务端撤销 |
| 代理、网络超时、429、401 撤销 | 分类和重试次数正确，错误没有秘密 |
| 成功 / 失败 / 取消 / 崩溃后的临时文件 | 无孤儿子进程；过期目录受限清理，真实 Home 不受影响 |
| file / auto / keyring / API Key 配置 | 保持已声明存储边界，不静默改模式或混用身份 |

自动化以假 App Server、临时目录和合成凭据为主；真实账号仅用于用户主动配合的必要冒烟，不打印凭据。Rust 变更执行 `cargo fmt --all` 与 `cargo test`；前端变更执行 `npm run format`、`npm run typecheck` 与 `npm run build:web`。增加针对通知乱序、取消和凭据竞争的行为测试，不为静态文案单独编写测试。

本文件后续阶段继续作为演进清单。已实现范围以开头“本次交付”为准；未执行真实账号登录或迁移。
