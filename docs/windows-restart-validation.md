# Windows 重启兼容性验证

这份清单用于验证“切换并重启”在不同 Windows 安装方式下的行为。CI 的 `cargo test --locked desktop_client::` 检查 Rust 编译和桌面客户端测试；真实包注册、系统激活和窗口状态仍需实机验证。未执行的项目应标为“未验证”，不能用 CI 通过代替。

## 准备

- 使用可恢复的 Windows 测试机或虚拟机，记录 Windows、Codex 和本工具的版本，以及 Codex 的安装来源。商店／MSIX 版与普通安装版分开测试；没有可用的普通安装版时，记录该场景未验证。
- 使用测试账号，在本工具中保存两个 ChatGPT 账号，使用默认 `CODEX_HOME`。测试前结束任务，只保留一个 Codex 桌面实例。
- 从开始菜单启动 Codex，确认它能正常显示窗口。在 Codex 内确认当前账号，切换后再次核对。
- 验证认证文件是否改动时，只在测试机本地比较前后哈希，记录“相同／不同”。不要显示、复制或上传 `auth.json`、账号库、令牌、Cookie 或完整环境变量；不要要求用户发送这些内容。
- 使用调试器或测试专用构建验证故障分支时，只调整本工具 Windows 兼容层的 API 返回值。不要为制造故障修改真实用户的包注册、权限或安装目录；完成后撤销测试改动。

## 实机验证

| 场景                | 操作                                                                                                     | 预期结果                                                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 商店／MSIX 正常重启 | 从开始菜单启动已注册的 Codex，记录主进程 PID；选择另一个账号并“切换并重启”。                             | 关闭前能从运行进程取得包全名和 AUMID，且 AUMID 属于当前用户已注册的包；原进程正常退出后通过 Windows 应用激活重开。新目标进程的 PID、包身份与启动目标相符，短暂观察期间持续运行，不出现“该进程没有程序包标识符”。最后在 Codex 内核对账号。 |
| 普通安装版正常重启  | 使用可识别为 OpenAI Codex、没有 Windows 包身份的正常安装版，执行同一操作。                               | 明确确认进程没有包身份后，直接启动原 EXE；新进程路径符合目标且持续运行。不会因没有包身份而尝试包激活。                                                                                                                                    |
| 客户端未运行        | 完全退出 Codex，再选择“切换并重启”。                                                                     | 仅切换账号，结果说明客户端未运行，不自动启动客户端。                                                                                                                                                                                      |
| 仅切换              | Codex 已退出时选择“仅切换”，然后从开始菜单打开。                                                         | 本工具不查询或控制客户端进程，凭据切换成功；手动打开后自行核对账号。                                                                                                                                                                      |
| 正常退出超时        | 在测试专用构建中让关闭后的退出检测持续返回“仍在运行”，等待超时。                                         | 操作报退出失败，不强杀进程，认证文件和账号库保持原样，不启动另一个实例。                                                                                                                                                                  |
| 多个桌面实例        | 在测试环境中运行两个可识别的桌面实例，再请求自动重启；无法真实启动两实例时通过测试构建提供两条实例记录。 | 在关闭或写入前拒绝自动重启，不任意选择一个实例。                                                                                                                                                                                          |

## 故障分支验证

下列故障可通过测试专用构建或调试器在对应的原生 API 封装处模拟。只注入所列故障，其他查询使用真实结果；若没有合适的调试环境，保留“未验证”，不要操作真实安装来强行复现。

| 场景                 | 注入或复现方法                                                                                   | 预期结果                                                                                          |
| -------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 包身份查询失败       | 让进程句柄打开或包全名查询返回访问被拒绝等错误，而不是“没有包身份”。                             | 关闭前拒绝自动重启，不把查询失败当作普通 EXE，也不修改凭据；仍可选择“仅切换”。                    |
| 包应用缺少 AUMID     | 保留有效包全名，让应用标识查询返回错误或空标识。                                                 | 关闭前拒绝自动重启，不从目录名称猜测应用标识，不直接启动包内 EXE。                                |
| 疑似包路径却没有身份 | 使用测试实例记录，将目标路径设为 Windows 包安装目录下的 Codex EXE，身份查询返回“没有包身份”。    | 拒绝自动重启，不将可能失去包上下文的 EXE 当作普通安装版启动。                                     |
| 当前用户包注册失效   | 保留进程的包全名及 AUMID，让当前用户注册检查返回未注册，或让注册信息不包含该 AUMID。             | 关闭前拒绝自动重启，原客户端和凭据保持原样，不尝试修复／重新注册包。                              |
| 激活失败             | 正常通过预检与关闭，在凭据写入后让 `ActivateApplication` 返回失败。                              | 结果区分“账号已切换”和“客户端启动失败”，提示手动打开；不回退为裸 EXE 启动，不回滚已经写入的账号。 |
| 激活后身份不符       | 让激活返回的 PID 不属于预期包，或使重启后的包身份核对失败。                                      | 不报告重启成功，不把其他 Codex 进程或系统代理进程当作目标。账号已写入的结果仍保留。               |
| 启动后立即退出       | 在隔离测试环境中，让已通过首次进程检查的目标在短暂观察期结束前退出；包版与普通安装版各执行一次。 | 报告启动失败，不因进程曾出现就报告成功；提示手动打开，保留账号已切换的事实。                      |

成功结果只说明目标进程通过身份核对并在观察期内保持运行。它不能证明窗口已就绪、没有弹窗、网络正常或 Codex 已采用目标账号；观察期后的崩溃也不能由本次检查保证发现。

## macOS 回归

1. 从正常安装的 `com.openai.codex` 应用打开 Codex，确认只有一个桌面实例。
2. 选择另一个账号并“切换并重启”，确认正常退出后打开原应用，最后在 Codex 中确认账号。
3. 完全退出 Codex 后再执行“切换并重启”，确认只切换、不自动启动。
4. 运行独立 Codex CLI 或 IDE 会话，确认桌面客户端重启不会关闭它们。此项只验证进程控制范围，不在会话中执行需要保留的工作。
5. 使用测试构建模拟退出超时，确认凭据保持原样；模拟重开失败，确认界面区分已完成的账号切换和未完成的重启。

## 记录结果

记录场景、系统与应用版本、安装来源、是否通过、界面提示和人工核对结论。必要时附遮盖个人信息后的错误弹窗截图。不要附认证文件、令牌、账号库或包含敏感信息的调试器内存转储。
