# 界面字体规范

字体变量统一定义在 `src/styles.css` 的 `:root` 中。组件按文字的语义选择变量，不按已有字号就近套用，也不通过缩小文字容纳更多内容。

## 字号

字号使用 `rem`，保留浏览器或系统的默认字号设置。下表中的像素值仅表示默认根字号为 16px 时的效果，不应将根字号固定为 16px 来锁定视觉大小。

| 变量             | 值         | 默认效果 | 用途                                                           |
| ---------------- | ---------- | -------- | -------------------------------------------------------------- |
| `--text-caption` | `0.75rem`  | 12px     | 辅助说明、字段提示、单位、时间戳、状态标签、表头、数据覆盖范围 |
| `--text-body`    | `0.875rem` | 14px     | 正文、按钮、输入框、选择框、字段标签、表格数据、费用明细       |
| `--text-heading` | `1rem`     | 16px     | 卡片标题、分组标题、折叠区标题、列表中的账号标题               |
| `--text-title`   | `1.5rem`   | 24px     | 页面或主要区域标题；账号名称等标题不使用统计数字字号           |
| `--text-stat`    | `1.75rem`  | 28px     | 卡片中的重点统计值、用量或费用估算总额                         |
| `--text-display` | `2rem`     | 32px     | 页面顶部的核心汇总数字                                         |
| `--text-chart`   | `0.625rem` | 10px     | 密集图表中的日期、月份等刻度，仅限刻度文字                     |

相邻信息应保持层级：大数字旁的单位用辅助字号，费用总额下的分项金额用正文字号。表格中的数字属于正文，不因内容为数字就使用统计字号。图表标题、图例、提示浮层和统计说明使用对应的正文或辅助字号，不能套用刻度字号。

## 字重与行高

| 变量                | 值     | 用途                         |
| ------------------- | ------ | ---------------------------- |
| `--weight-regular`  | `400`  | 正文、辅助说明               |
| `--weight-medium`   | `500`  | 字段标签、需要轻度强调的正文 |
| `--weight-semibold` | `600`  | 按钮、卡片标题、重点数据     |
| `--weight-bold`     | `700`  | 核心标题、关键汇总值         |
| `--leading-tight`   | `1.3`  | 标题、独立统计数字、紧凑标签 |
| `--leading-normal`  | `1.5`  | 正文、控件、多行表格内容     |
| `--leading-relaxed` | `1.65` | 较长的帮助文字、说明与提示   |

行高使用无单位值，随字号自然缩放。不要为普通文字新增零散的字号、字重或行高；新增组件优先复用上述变量。需要新的层级时，先确认现有语义无法表达，再统一调整变量及本规范。

## 数字与布局

- 对费用、百分比、Token 数量、时间等需要纵向或动态比较的数值使用 `font-variant-numeric: tabular-nums`，减少更新时的宽度跳动。
- 容器应允许文字增长。Grid 使用 `minmax(0, 1fr)`，Flex 子项按需设置 `min-width: 0`，并在空间不足时换行、降列或纵向排列。
- 金额和重要统计值应保持完整可读，优先让标签与数字分行；不要通过缩字或裁切隐藏金额。长账号名、路径等允许按实际用途换行或省略，但需保留可查看完整内容的方式。
- 数据表格保留必要的横向滚动；不要缩小表格字体以强行塞入窗口。字号变大后，行高应允许内容自然撑开。
- 图表刻度字号或星期栏宽度变化时，同时检查热力图网格的预留宽度和间距，避免标签覆盖数据。
- 页面至少适应 760px 宽的窗口，并兼顾常用桌面宽度。响应式判断应考虑侧栏和内边距后实际可用的内容宽度，而非只看整个窗口宽度。

## 例外边界

- `aria-hidden` 的装饰动画内部可保留与画面比例相关的固定字号，例如动画里的文件名、浏览器示意文字和状态符号。这些文字不承担操作指导或必要信息。
- `+`、`×`、`✓` 等作为图形使用的符号可按图标尺寸设置；所在控件的可访问名称仍需清晰。
- 不要根据类名含 `scene`、`flow` 或元素带 `small` 就判断为装饰。实际流程步骤、按钮、帮助说明、错误提示仍遵守语义字号。
- `--text-chart` 不能用作压缩一般文字的替代方案，也不能因空间不足而把交互控件降到刻度字号。

## 修改与验收

前端修改后运行仓库现有检查：

```sh
npm run format
npm run typecheck
npm run build:web
```

再通过浏览器检查实际界面：

- 在 760px 窗口和常用桌面宽度下查看账号、Token 用量、订阅额度、用量价值模拟及相关弹窗。
- 分别查看简体中文、英文和亮色、暗色主题，确认标题、正文、辅助信息的层级一致，文字对比清楚。
- 使用较长的账号名、模型名、大金额和带小数的百分比，检查按钮、数字输入、表格、图表和卡片是否溢出、裁切或遮挡。
- 检查系统默认字号变化或浏览器缩放后的换行与滚动，确认内容仍完整、控件仍可操作。
- 对比分组标题、统计总额和明细数字，确认继承或更高优先级的选择器没有覆盖预期层级；同时确认装饰动画未被统一字号破坏。
