# Codex Auth Switch v1.4.1

> 修复切换账号后的本地项目排序，并改进 macOS 与 Windows 的退出检测。

## 修复与改进

- **沿用原账号的项目排序**：同时处理项目列表和统一侧栏的排序记录。已有项目按原账号保存的顺序排列，目标账号独有项目及其相对顺序保留；同目录但不同项目 ID 会映射到目标账号已有项目，保留其名称和设置。
- **支持仅更新排序**：即使没有新增项目，也会保存排序变化并显示对应结果；重复执行且排序一致时无需再次写入。原账号未保存明确顺序时，不使用项目 ID 的字典顺序重排已有项目。
- **修复 macOS 退出超时误判**：已识别框架路径下的独立崩溃报告器不再阻止退出确认，避免主程序已退出却因残留 `browser_crashpad_handler` 提示“Codex 未能正常退出”。工作进程、更新器及未知后台进程仍需正常退出，不强制结束任何进程。
- **改进 Windows 退出检测**：目标在读取快照与发送关闭请求之间正常退出时，会重新确认进程是否消失；父子关系同时核对映像路径和创建时间，避免父 PID 复用造成错误归类。进程查询只返回必要字段，并补充隔离 PowerShell 回归测试与 Windows CI 检查。

## 升级与使用

1. 从项目顺序正确的账号开始；若原账号的顺序也已打乱，先在 Codex 中调整一次。
2. 切换到目标账号时，保持“切换时沿用本地项目”开启，选择“切换并重启”，或先完全退出 Codex。
3. 重新打开后检查项目顺序和当前账号。沿用项目仍使用原有备份与并发写入保护，云端绑定、冲突及未知结构的项目继续跳过。

Windows 当前自动重启检测识别 OpenAI Codex 的 `Codex.exe`。独立的报告器／更新器不会触发目录扫描式误判；若报告器复用 `Codex.exe`，当前仍无法仅凭名称和路径与工作进程安全区分，可能继续阻止退出确认。`ChatGPT.exe` 形态及真实窗口／商店包行为仍需对应版本的实机验证，不能把无窗口或孤儿进程直接视为已退出。详见 [Windows 重启兼容性验证](https://github.com/Mintimate/codex-auth-switch/blob/v1.4.1/docs/windows-restart-validation.md)。

这些能力属于本地兼容实现，后续 Codex 版本可能需要适配；不新增后台服务或遥测，也不会改写会话正文、会话数据库或模型提供商配置。

## 下载与安装

- macOS：按设备选择 Apple Silicon 或 Intel 的 DMG；Windows：选择 x64 EXE 或 MSI；Linux：选择 x64 AppImage、Deb 或 RPM。
- `.app.tar.gz`、`.sig` 和 `latest.json` 用于应用内更新，手动安装无需下载。
